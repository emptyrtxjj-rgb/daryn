# 🦉 Дарын — AI-квиз по СОР, СОЧ и контрольным

Образовательный веб-сайт для школьников Казахстана: загружаешь PDF/DOCX с тестом — получаешь интерактивный квиз в стиле Duolingo с объяснением каждого ответа, проверкой открытых ответов и персональным напутствием.

- 🇰🇿/🇷🇺 Интерфейс на казахском и русском (переключатель KZ/RU).
- 📄 Загрузка PDF, DOCX (бонусом — TXT).
- 🧠 Gemini Flash разбирает задания и возвращает строгий JSON на языке документа.
- 🎮 Один вопрос на карточку, прогресс-бар, мгновенная обратная связь.
- ✍️ Открытые ответы оцениваются по критериям через Gemini.
- 🏆 Финальный экран: баллы, разбор ошибок и тёплый совет от «Дарына».
- 🧪 Демо-квиз работает без API-ключа — можно посмотреть весь UX сразу.

> **Статус:** весь интерфейс, демо-сценарий и серверные ошибки протестированы. Реальный вызов Gemini нужно проверить со своим `GEMINI_API_KEY` — без ключа приложение работает в демо-режиме.

## Быстрый старт

### 1. Требования

- Node.js **20+** (проверь: `node -v`)
- npm 10+
- API-ключ Gemini с доступом к `gemini-3-flash-preview`

### 2. Получи ключ Gemini

1. Открой [Google AI Studio](https://aistudio.google.com/apikey).
2. Создай API key.
3. Скопируй его — он понадобится на следующем шаге.

Бесплатного тарифа достаточно для тестов, но у него есть лимиты запросов в минуту/день. При превышении сервер вернёт понятную ошибку, а интерфейс предложит подождать.

### 3. Установи зависимости

```bash
cd C:\Users\user\Downloads\session
npm install
```

### 4. Создай `.env`

Windows PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
```

macOS/Linux:

```bash
cp .env.example .env
nano .env
```

Вставь ключ:

```env
GEMINI_API_KEY=твой_ключ_из_AI_Studio
GEMINI_MODEL=gemini-3-flash-preview
GEMINI_FALLBACK_MODELS=gemini-3.7-flash,gemini-3.1-flash-lite
GEMINI_TIMEOUT_MS=110000
PORT=3000
MAX_FILE_MB=15
AI_RATE_LIMIT=30
TRUST_PROXY=0
```

### 5. Запусти

```bash
npm start
```

Открой **http://localhost:3000**.

Для разработки с автоперезапуском:

```bash
npm run dev
```

### 6. Проверь без ключа

Даже без `GEMINI_API_KEY` на главной работает кнопка **«Посмотреть демо-квиз»**. Она открывает готовый квиз из 6 вопросов (4 тестовых + 2 открытых) и позволяет пройти весь сценарий: ответы, объяснения, результаты, разбор ошибок.

## Архитектура

```
┌──────────────────────────────────────────────────────────────────┐
│ Browser                                                          │
│  index.html  ── upload PDF/DOCX ──┐                              │
│  quiz.html   ── MC: local JSON    │                              │
│              ── open: POST        │                              │
│  results     ── POST /api/summary │                              │
└───────────────────────────────────┼──────────────────────────────┘
                                    │
                     Express + multer (memoryStorage)
                                    │
                    ┌───────────────▼────────────────┐
                    │ src/extract.js                 │
                    │ pdf-parse / mammoth / TXT      │
                    │ scanned PDF → inline PDF       │
                    └───────────────┬────────────────┘
                                    │ text or PDF bytes
                    ┌───────────────▼────────────────┐
                    │ src/gemini.js                  │
                    │ Gemini Flash                   │
                    │ responseMimeType: application/ │
                    │ json                           │
                    └───────────────┬────────────────┘
                                    │ raw JSON
                    ┌───────────────▼────────────────┐
                    │ src/normalize.js               │
                    │ валидация, ремонт, баллы, lang │
                    └───────────────┬────────────────┘
                                    │ quiz JSON
                          sessionStorage ('daryn.quiz')
                                    │
                             quiz.html / quiz.js
                                    │
              ┌─────────────────────┴─────────────────────┐
              │ MC: ответы и объяснения уже в JSON        │
              │ Open: /api/check-open-answer → Gemini      │
              │ Итог: /api/summary → Gemini                │
              └───────────────────────────────────────────┘
```

**Почему так:**

- **Нет базы данных** — квиз живёт в `sessionStorage` между страницами. Это fastest-to-ship вариант и он не хранит работы школьников на сервере.
- **Нет сборки** — чистый HTML/CSS/JS + Tailwind CDN. Открыл и работает.
- **Контент и интерфейс разделены** — переключатель KZ/RU меняет только подписи. Язык заданий всегда берётся из загруженного документа.
- **MC не ходит в API** — все объяснения сгенерированы заранее и лежат в JSON. Это быстро, бесплатно и работает даже при исчерпанной квоте.
- **Открытые ответы и финальный совет** — единственные живые вызовы Gemini после генерации квиза.

## Как работает пайплайн

1. **Загрузка.** `POST /api/generate-quiz` принимает один файл в поле `file`. Multer держит его в памяти, файл не пишется на диск.
2. **Валидация.** Проверяются расширение, размер и magic bytes (`%PDF-`, `PK` для DOCX). Лимит — 15 МБ.
3. **Извлечение текста.**
   - PDF → `pdf-parse`.
   - DOCX → `mammoth.extractRawText`.
   - TXT → UTF-8.
   - Если у PDF нет текстового слоя (скан), сервер отправляет сам PDF в Gemini как `inlineData`. Ограничение этого fallback — 10 МБ.
4. **Генерация.** `src/gemini.js` вызывает `gemini-3-flash-preview` с `responseMimeType: "application/json"`, системным промптом и текстом документа (до 120 000 символов).
5. **Нормализация.** `src/normalize.js` проверяет JSON, чинит типы, удаляет битые вопросы, считает `total_points`, определяет язык и добавляет fallback-объяснения.
6. **Передача в браузер.** Квиз сохраняется в `sessionStorage` под ключом `daryn.quiz`, происходит переход на `/quiz.html`.
7. **MC-вопросы.** Фронтенд сравнивает выбранный индекс с `correct_index` и показывает заранее сгенерированные `explanation` и `mistake_explanation`. Никаких запросов к API.
8. **Open-вопросы.** `POST /api/check-open-answer` отправляет вопрос, критерии, пример ответа и текст ученика в Gemini. Модель ставит балл по критериям и пишет фидбек.
9. **Итоги.** `POST /api/summary` получает баллы и темы ошибок, возвращает короткое напутствие и один практический совет на языке документа.
10. **Результаты.** Фронтенд считает процент, рисует кольцо, показывает разбор каждой ошибки, конфетти и кнопки «Пройти ещё раз» / «Новый тест».

### Ограничения пайплайна

- До **40 вопросов** за один раз.
- Текст документа обрезается до **120 000 символов**.
- Нет chunking: очень длинный тест может потерять хвост. Для MVP это осознанный компромисс.
- Скан без текста отправляется как PDF, но только если файл ≤ 10 МБ.
- Ответы MC проверяются на клиенте; это образовательный тренажёр, а не защищённый экзамен.

## API

Все ответы — JSON. Ошибки имеют вид:

```json
{ "error": "MISSING_API_KEY", "message": "GEMINI_API_KEY is not configured on the server" }
```

### `GET /api/health`

Проверка сервера и наличия ключа.

```json
{
  "ok": true,
  "gemini": true,
  "model": "gemini-3-flash-preview"
}
```

### `GET /api/demo?lang=ru|kz`

Возвращает готовый демо-квиз. Ключ Gemini не нужен.

```json
{ "ok": true, "quiz": { "language": "ru", "questions": [] } }
```

### `POST /api/generate-quiz`

`multipart/form-data`, поле `file`.

```bash
curl -X POST http://localhost:3000/api/generate-quiz \
  -F "file=@sor_7_klass.pdf"
```

Успех:

```json
{
  "ok": true,
  "quiz": {
    "language": "ru",
    "title": "СОР по математике",
    "subject": "Математика",
    "grade": "7 класс",
    "question_count": 12,
    "total_points": 17,
    "questions": []
  },
  "meta": {
    "filename": "sor_7_klass.pdf",
    "method": "pdf-parse",
    "characters": 18432,
    "pages": 3
  }
}
```

### `POST /api/check-open-answer`

```json
{
  "question": "Почему вода в реке замерзает сверху?",
  "criteria": [
    "Лёд легче воды и остаётся на поверхности",
    "Вода имеет максимальную плотность при +4 °C",
    "Лёд защищает нижние слои от промерзания"
  ],
  "max_score": 3,
  "sample_answer": "Лёд легче воды...",
  "answer": "Потому что лёд легче и не тонет...",
  "language": "ru"
}
```

Ответ:

```json
{
  "ok": true,
  "grade": {
    "score": 2,
    "max_score": 3,
    "percent": 67,
    "verdict": "partial",
    "feedback": "Ты верно заметил, что лёд легче воды. Добавь, почему вода замерзает именно при +4 °C...",
    "criteria_results": [
      { "criterion": "Лёд легче воды...", "met": "yes", "comment": "Верно." },
      { "criterion": "Вода имеет максимальную плотность...", "met": "no", "comment": "Этого в ответе нет." }
    ]
  }
}
```

`max_score` на сервере пересчитывается по количеству критериев (1–5), клиентское значение не используется для завышения балла.

### `POST /api/summary`

```json
{
  "score": 14,
  "total": 17,
  "language": "ru",
  "correct": 11,
  "question_count": 17,
  "mistakes": [
    { "topic": "Дроби", "question": "Сколько будет 3/4 + 1/8?" }
  ]
}
```

Ответ:

```json
{
  "ok": true,
  "summary": {
    "message": "Ты хорошо потрудился и почти разобрался с дробями...",
    "tip": "Повтори приведение к общему знаменателю и реши 3 похожих примера.",
    "emoji": "🌟"
  }
}
```

### Коды ошибок

| Код | HTTP | Что значит |
|---|---|---|
| `NO_FILE` | 400 | Файл не передан. |
| `UNSUPPORTED_FILE` / `INVALID_FILE` | 415 / 400 | Не PDF/DOCX/TXT или повреждённый файл. |
| `FILE_TOO_LARGE` | 413 | Файл больше `MAX_FILE_MB`. |
| `EMPTY_DOCUMENT` / `DOCX_EXTRACT_FAILED` | 422 | Не удалось извлечь текст. |
| `PDF_SCAN_TOO_LARGE` | 422 | Скан без текста больше 10 МБ. |
| `MISSING_API_KEY` | 503 | Нет `GEMINI_API_KEY`. |
| `AI_RATE_LIMIT` | 429 | Лимит Gemini / слишком много запросов. |
| `AI_AUTH` | 502 | Невалидный ключ или нет доступа. |
| `AI_TIMEOUT` | 504 | Gemini не ответил вовремя. |
| `AI_BAD_JSON` / `AI_EMPTY_RESPONSE` | 502 | Модель вернула не JSON или пустой ответ. |
| `NO_QUESTIONS` | 422 | В документе не найдены вопросы. |
| `EMPTY_ANSWER` | 400 | Пустой открытый ответ. |
| `APP_RATE_LIMIT` | 429 | Локальный лимит приложения (30 запросов / 15 мин). |
| `INTERNAL_ERROR` | 500 | Непредвиденная ошибка сервера. |

## JSON-контракт квиза

Модель обязана вернуть ровно один JSON-объект. Сервер дополнительно всё проверяет.

```json
{
  "language": "ru",
  "title": "СОР по биологии",
  "subject": "Биология",
  "grade": "8 класс",
  "questions": [
    {
      "type": "multiple_choice",
      "topic": "Фотосинтез",
      "question": "Какой газ растения поглощают при фотосинтезе?",
      "options": ["Кислород", "Углекислый газ", "Азот", "Водород"],
      "correct_index": 1,
      "explanation": "Растение использует CO₂ и воду, а на свету производит глюкозу и выделяет кислород.",
      "mistake_explanation": "Кислород растения выделяют, а не поглощают. Не путай газ-реагент и газ-продукт."
    },
    {
      "type": "open_answer",
      "topic": "Плотность воды",
      "question": "Почему вода в реке замерзает сверху?",
      "criteria": [
        "Лёд легче воды и остаётся на поверхности",
        "Вода имеет максимальную плотность при +4 °C",
        "Лёд защищает нижние слои от промерзания"
      ],
      "max_score": 3,
      "sample_answer": "Лёд легче воды, поэтому остаётся на поверхности...",
      "explanation": "Плотность льда меньше плотности воды, а максимум плотности воды — при +4 °C."
    }
  ]
}
```

**Что делает `normalize.js`:**

- приводит `type` к `multiple_choice` / `open_answer`;
- проверяет `options` и `correct_index`, умеет восстановить индекс из `correct_answer` (текст или буква);
- удаляет вопросы без вариантов/критериев и считает `skipped_questions`;
- гарантирует, что `max_score` открытого вопроса равен числу критериев;
- подставляет безопасные объяснения, если Gemini их пропустил;
- определяет язык по казахским буквам/словам, если `language` отсутствует;
- считает `total_points` (MC = 1 балл, open = число критериев);
- добавляет `id`, `points`, `question_count`, `created_at`.

## Оценивание

| Тип | Баллы |
|---|---|
| `multiple_choice` | 1 балл за верный вариант, 0 за неверный. |
| `open_answer` | 0…N, где N — число критериев (1–5). 1 балл за полностью выполненный критерий, 0.5 за частично. |

- Итог показывается как `получено / максимум` (например, `14 / 17`).
- Процент считается по баллам, а не по количеству вопросов.
- «Верных» на экране результатов — вопросы, набравшие максимум.
- «Ошибок» — вопросы, где `awarded < max` (частичный ответ тоже попадает в разбор).
- В демо-режиме открытые ответы оцениваются **локально по ключевым словам**. Это честно подписано в интерфейсе; такой оценке нельзя доверять как настоящей.

## Промпты

Все промпты лежат в `src/prompts.js`.

### Генерация квиза

- Определить язык документа и писать **все** тексты на нём.
- Извлечь только реальные вопросы, не выдумывать; если есть ключ ответов — использовать его, иначе решить задания самостоятельно.
- До 40 вопросов, в порядке документа.
- Для MC: 2–6 вариантов, ровно один правильный, `correct_index` с нуля, `mistake_explanation` про типичную ошибку.
- Для open: 2–5 проверяемых критериев, `max_score = criteria.length`, `sample_answer`.
- `explanation` — настоящая предметная наука, 1–3 предложения, без «вариант А правильный».
- Вернуть только JSON, без markdown и комментариев.

### Проверка открытого ответа

- Оценивать **только по критериям**, 1 / 0.5 / 0 за каждый.
- Не требовать дословного совпадения с примером.
- Фидбек — 2–3 тёплых предложения: что получилось, чего не хватает, как улучшить.
- Вернуть `score`, `max_score`, `feedback`, `criteria_results` (yes/partial/no + комментарий).
- Язык — язык вопроса.

### Финальное напутствие

- 2–3 предложения поддержки + один конкретный совет по темам ошибок.
- Не стыдить, не преувеличивать, не упоминать, что ты ИИ.
- Вернуть `message`, `tip`, `emoji`.
- Язык — язык документа.

`responseMimeType: "application/json"` включён для всех трёх вызовов. Дополнительно `gemini.js` умеет:
- снимать code fences;
- находить JSON внутри текста;
- повторять запрос один раз при 429/5xx/битом JSON;
- маппить ошибки SDK в понятные коды.

Чтобы менять качество/стиль, правь только `src/prompts.js` — структура ответа и валидация останутся прежними.

## Демо-режим

Демо нужно, чтобы:

- посмотреть дизайн и весь flow без ключа;
- проверять фронтенд после изменений;
- показывать проект на созвоне/защите.

Как работает:

- `GET /api/demo?lang=ru|kz` отдаёт готовый квиз из `src/demo-data.js`.
- В нём 6 вопросов: 4 MC + 2 open, 9 баллов.
- MC проверяются как обычно.
- Open-ответы в демо оцениваются **на клиенте** по пересечению ключевых слов с критериями и примером ответа. В фидбеке и на результатах явно написано, что это демо без ИИ.
- Итоговый совет тоже локальный.

**Важно:** демо может не засчитать правильный пересказ, потому что сравнивает слова, а не смысл. Это ожидаемо и подписано в UI. Настоящая оценка смысла — только через Gemini.

## Ограничения и безопасность

### Что уже сделано

- Ключ Gemini используется только на сервере, не попадает в браузер.
- Multer `memoryStorage`: файлы не сохраняются на диск.
- Ограничение размера файла, количества файлов и полей.
- Проверка magic bytes для PDF/DOCX.
- Rate limit на все AI-маршруты (30/15 мин на IP по умолчанию).
- Лимиты длины текста, критериев и ответа.
- Ошибки не раскрывают ключ и внутренние детали.
- XSS-безопасный рендеринг: тексты от Gemini вставляются через `textContent`, а не `innerHTML`.

### Чего пока нет

- Авторизации и личных кабинетов.
- Базы данных и истории прохождений.
- Защиты от накрутки баллов (MC считаются на клиенте).
- Серверного хранения файлов и квизов.
- Полноценного OCR для сканов: используется нативное понимание PDF Gemini, но только до 10 МБ.
- CSP: Tailwind подключён через CDN, поэтому строгая политика не настроена.
- Chunking длинных документов: текст обрезается на 120k символов, вопросы — на 40.
- Production-сборки Tailwind (CDN удобен для MVP, но требует интернета).

### Про `npm audit`

Сейчас `npm audit --omit=dev` показывает **3 moderate** уязвимости в цепочке `mammoth → argparse → sprintf-js`. Автоматический фикс предлагает откатить mammoth до 0.3.x — это ломающее изменение, которое не подходит. Уязвимость связана с CLI-парсингом `argparse`, а не с извлечением текста из DOCX в нашем сценарии. Следи за обновлениями `mammoth`; перед публичным запуском стоит перепроверить аудит.

### Если выкладываешь публично

- Поставь `TRUST_PROXY=1` за reverse-proxy.
- Уменьши `AI_RATE_LIMIT` или добавь авторизацию, чтобы не сжечь квоту.
- Добавь мониторинг 429/5xx.
- Не храни работы школьников без согласия.
- Проверь условия использования Gemini API и закон о персональных данных.

## Деплой

Подойдёт любой Node-хостинг: Render, Railway, Fly.io, VPS с PM2/Nginx.

### Render / Railway

1. Залей проект в GitHub (без `.env` и `node_modules`).
2. Создай Web Service.
3. Build command: `npm install`.
4. Start command: `npm start`.
5. Environment variables:
   - `GEMINI_API_KEY`
   - `GEMINI_MODEL=gemini-3-flash-preview`
   - `GEMINI_FALLBACK_MODELS=gemini-3.7-flash,gemini-3.1-flash-lite`
   - `TRUST_PROXY=1`
   - при необходимости `AI_RATE_LIMIT`
6. Открой выданный URL.

### VPS + Nginx

```bash
npm ci --omit=dev
pm2 start server.js --name daryn
pm2 save
```

Nginx проксирует `127.0.0.1:3000`. Не забудь `TRUST_PROXY=1` и HTTPS.

### Важно про таймауты

Генерация квиза может занимать 10–60 секунд (особенно PDF-скан). Сервер держит сокет до 5 минут (`server.timeout = 300000`), а фронтенд ждёт ответ до 5 минут через `AbortController`. Если используется Nginx, Cloudflare или туннель, увеличь таймаут и там: `proxy_read_timeout 300s`; у бесплатного Cloudflare лимит около 100 секунд. Иначе соединение оборвёт прокси, а не Express.

## План запуска для вайбкодера

Пошагово, без лишней теории:

1. **Установи зависимости.**
   ```bash
   npm install
   ```
2. **Возьми ключ** в [AI Studio](https://aistudio.google.com/apikey).
3. **Создай `.env`** из `.env.example` и вставь ключ.
4. **Запусти** `npm start` и открой `http://localhost:3000`.
5. **Проверь демо** — кнопка «Посмотреть демо-квиз». Пройди все 6 вопросов, включая открытые, дойди до результатов.
6. **Проверь реальную загрузку** на простом PDF с текстовым слоем: 3–5 вопросов, чтобы генерация заняла меньше времени.
7. **Проверь открытый ответ** в реальном квизе — это единственное место, где качество промпта видно сразу.
8. **Подкрути промпт** в `src/prompts.js`, если объяснения слишком длинные/короткие или Gemini путает типы вопросов. Структуру JSON не меняй без правки `normalize.js`.
9. **Закоммить** проект без `.env` и `node_modules`.
10. **Задеплой** на Render/Railway, добавь env-переменные и проверь прод-URL на телефоне.
11. **Дальше** — авторизация, история, teacher dashboard, экспорт результатов.

## Troubleshooting

| Симптом | Что делать |
|---|---|
| `GEMINI_API_KEY is not configured` | Создай `.env` из `.env.example`, вставь ключ, перезапусти `npm start`. |
| `AI_AUTH` | Ключ неверный/удалён/без доступа к модели. Создай новый в AI Studio. |
| `AI_RATE_LIMIT` / 429 | Исчерпан лимит бесплатного тарифа. Подожди минуту/сутки или включи биллинг. |
| `AI_BAD_JSON` | Модель вернула не JSON. Попробуй ещё раз; если повторяется — упрости промпт или уменьши документ. |
| `NO_QUESTIONS` | В файле нет распознаваемых вопросов. Проверь, что это тест, а не теория. |
| Скан PDF не читается | Нужен текстовый слой или PDF ≤ 10 МБ. Можно прогнать через OCR заранее. |
| DOCX не читается | Проверь, что это настоящий `.docx`, а не переименованный `.doc`. |
| Долгая генерация | Это нормально для больших PDF. Не закрывай вкладку; на проде увеличь timeout. |
| Порт 3000 занят | Измени `PORT` в `.env` или останови старый процесс. |
| Стили сломались без интернета | Tailwind подключён через CDN. Для офлайна собери CSS локально. |
